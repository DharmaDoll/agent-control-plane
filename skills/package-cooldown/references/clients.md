# Client recipes

Resolve paths for the installed version and current environment. Common paths below are examples. Use integer D for days, M = 1440 × D for minutes and S = 86400 × D for seconds. Substitute values as individual arguments. Check support against the installed CLI's help, bundled docs/schema or version-matched upstream documentation. Check the current project, its ancestors/workspace root, user and system config and applicable environment variables. Query the specific key; when a CLI only lists all settings, filter locally before output. Use a parser appropriate for the file format. Treat includes, aliases, executable config and unresolved substitutions as unknown unless the client can safely resolve them.

| Client and coverage | Inspect and apply recipe |
| --- | --- |
| [npm](https://docs.npmjs.com/using-npm/config/#min-release-age), npm tree resolution | Check bundled config definitions for min-release-age. Get the destination with `npm config get userconfig`. Check project .npmrc, globalconfig, npm_config_* overrides, before and min-release-age-exclude. Compare `npm config get min-release-age` in a neutral directory and the project. Write with `npm config set min-release-age=D --location=user`. |
| [pnpm](https://pnpm.io/settings#minimumreleaseage), registry resolution | Check minimumReleaseAge and minimumReleaseAgeExclude, pnpm-workspace.yaml, includes and per-version global config. Check the documented version default (v11 introduced a one-day default). Use `pnpm config get minimumReleaseAge` and confirm the actual global config path with the installed CLI. Where global config writes this key to user scope, use `pnpm config set --global minimumReleaseAge M`. Re-read the affected file as well as the project result. |
| [Modern Yarn](https://yarnpkg.com/configuration/yarnrc/#npmMinimalAgeGate), npm resolution | Check npmMinimalAgeGate, npmPreapprovedPackages, ancestor .yarnrc.yml files and YARN_* overrides. Yarn Classic uses a different configuration system. Use `yarn config get npmMinimalAgeGate`; confirm the installed version's supported duration syntax (older releases use minutes). Use `yarn config set --home npmMinimalAgeGate VALUE` with the verified syntax, e.g. 7d for duration strings. |
| [Bun](https://bun.com/docs/pm/cli/install#minimum-release-age), newly resolved registry packages | Check install --help and the applicable global and project bunfig.toml, install.minimumReleaseAge and minimumReleaseAgeExcludes. Use the bun file recipe for the resolved user .bunfig.toml. Existing lockfile entries may be reused. |
| [pip](https://pip.pypa.io/en/stable/cli/pip_install/#cmdoption-uploaded-prior-to), index resolution | Bind every command to the same interpreter (`python -m pip`). Check install --help explicitly supports P<n>D. Inspect pip.conf files including legacy, site/virtualenv and PIP_CONFIG_FILE, plus PIP_UPLOADED_PRIOR_TO and command sections. Verify user destination using the installed pip configuration rules. Use `python -m pip config --user set global.uploaded-prior-to P7D` substituting D. Recheck global and install sections. Effect requires index upload timestamps. |
| [uv](https://docs.astral.sh/uv/reference/settings/#exclude-newer), index resolution | Check relative-duration support, UV_EXCLUDE_NEWER, UV_CONFIG_FILE, project/workspace uv.toml and pyproject.toml tool.uv, user/system uv.toml and exclude-newer-package. Use the uv file recipe at the resolved user uv.toml. A date is an existing explicit policy. Report upload age per artifact. |
| [Bundler and RubyGems](https://guides.rubygems.org/command-reference/bundle-config/), gem resolution | Check each installed client's help for cooldown. Inspect bundle config get cooldown, BUNDLE_COOLDOWN, project .bundle/config, per-source Gemfile settings (static only), gemrc :cooldown: and command-specific flags. Apply `bundle config set --global cooldown D` to the resolved Bundler user config or the gem file recipe for RubyGems. Check both again after either write: supported versions share cooldown information. Preserve explicit source-specific policies. |
| [Cargo](https://doc.rust-lang.org/cargo/reference/config.html#registries), crate resolution | Requires Cargo 1.100+ for publish-age enforcement. Check registry.global-min-publish-age, registries.*.min-publish-age, resolver.incompatible-publish-age, CARGO_* overrides, ancestor .cargo configs and legacy extensionless config. Apply the cargo file recipe to the active user config.toml only when deny applies. Report coverage limits for missing pubtime and Cargo.lock entries. |
| [Composer](https://getcomposer.org/doc/06-config.md#cooldown), update/require | Use --no-plugins --no-scripts for every probe and write. Resolve home with `composer --no-plugins --no-scripts config --global home`; user file is config.json there. Inspect config.policy, policy.cooldown.period, exemptions, project composer.json and COMPOSER_POLICY_COOLDOWN_PERIOD. Verify the installed schema supports the key. Use `composer --no-plugins --no-scripts config --global policy.cooldown.period "D days"` when its config command accepts the nested key. Check the saved type and effective config. |
| Go | Locate go and report native policy unverified. An updater's waiting period governs only updates through that service. |

## File recipe

For bun, uv, cargo and gem use Python 3.11+ on POSIX. After the inspections above, run `python3 scripts/file_setting.py TOOL ABSOLUTE_USER_PATH --days D` relative to the skill directory. The preview reads without creating directories and returns an opaque review token. Use the same arguments plus `--apply TOKEN` only for the reviewed change. The helper limits edits to inserting one missing key, compares parsed TOML before and after, and uses file replacement in the same directory. It only handles empty or comment-only gemrc files. Report richer gemrc files and noncanonical TOML layouts requiring manual editing. Keep shared or concurrently managed config files in inspect mode. The helper does not discover CLI support, defaults, exemptions or overrides; complete those checks before using it.
